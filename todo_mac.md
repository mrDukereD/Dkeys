# todo_mac — план переноса DKeys на macOS

## Исходники и с чего начать (для того, кто делает порт на Mac)

Репозиторий: **https://github.com/mrDukereD/Dkeys** (ветка `main`).

```bash
git clone https://github.com/mrDukereD/Dkeys.git
cd Dkeys
```

Что смотреть в репозитории (локальных файлов автора не нужно):

- `README.md` — полный список функций и поведения; это техническое задание для порта.
- `CHANGELOG.md` — история версий, что и когда появилось.
- `CLAUDE.md` — устройство проекта, грабли (буфер обмена, хоткеи, модификаторы), правила локализации.
- `src/dkeys.cpp` — вся Windows-программа (чистый WinAPI, ~10,7 тыс. строк); читать как справочник логики, не как код для переноса.
- `src/calendar.h`, `src/calview.h`, `src/calsync.h` — ядро календаря без интерфейса; можно переиспользовать (этап 11).
- `calendars/` — скрипты-провайдеры синхронизации на Python (`caldav.py`, `google.py`, `outlook.py`, `gtasks.py`) и `README.md` с договором; переиспользуются как есть.
- `scripts/` — примеры пользовательских скриптов (`.py`, `.dpy`).
- `tests/` — тесты ядра календаря (`run.cmd` — для Windows, на Mac собрать clang-ом по тем же исходникам).
- `TODO.md` — общий список задач проекта.

План актуален на версию **1.7 + правки до 2026-11-17** (коммит `056f01c`): учтены быстрый запуск `[QuickRun]`, примеры скриптов календаря, подсветка курсора и кольца кликов при записи, настройки оверлеев по мониторам. Новее — смотреть `git log` и `CHANGELOG.md`.

Порт — новый проект на Swift: создать в репозитории папку `DKeysMac/` (или отдельный репозиторий) и идти по этапам ниже. Windows-версию не менять. Перед коммитом проверять, что в репозиторий не попадают личные пути, ключи и токены (см. `.gitignore`).

Не порт C++, а новый проект на Swift (AppKit, при необходимости SwiftUI) с той же идеей: маленькая утилита в строке меню, мультибуфер, хоткеи, раскладка, экранные утилиты. Этапы идут от простого к тяжёлому: на каждом получается рабочая программа, которой можно пользоваться. Оценки — для одного разработчика, в рабочих неделях.

## Решения до начала (этап 0)

- [ ] **Язык и сборка:** Swift 5.9+, Swift Package Manager + Xcode-проект; минимальная macOS — 13 (нужен `ScreenCaptureKit` и `SMAppService`). Apple Silicon + Intel (universal).
- [ ] **Название и bundle id:** `DKeys`, `by.dukered.dkeys` (или свой). Репозиторий — отдельная папка `DKeysMac/` в том же git или отдельный репо; общие скрипты (`calendars\*.py`, `scripts\`) переиспользуются.
- [ ] **Apple Developer ($99/год):** без подписи и нотаризации разрешения слетают, Gatekeeper ругается. Решить сразу: платный аккаунт или ad-hoc подпись для личного использования (тогда после каждой пересборки заново выдавать права).
- [ ] **Раскладка клавиш:** соответствие Win → Cmd/Ctrl/Option; хоткеи `Win+Num1..9` заменить (на Mac нет NumPad у ноутбуков) — предложить `Ctrl+Opt+1..9` и т. п. Таблицу замен записать в README.
- [ ] **Хранение:** `~/Library/Application Support/DKeys/` (`memory/`, `scripts/`, `records/`, `calendars/`, `langs/`) и `DKeys.ini` там же, формат ini сохранить (скрипты и документация совместимы). Режим «portable» не нужен.
- [ ] **Окружение для проверки:** физический Mac или VM (на Windows VM с macOS не запустить легально/нормально — нужен реальный Mac). Без него не начинать этапы 1+.
- [ ] **Локализация:** `Localizable.strings` (ru/en/ar) вместо `LANG_LIST`; ключи — те же, что в `Tr(L_ID)`, чтобы переводы можно было перенести скриптом.

Срок: 0,5 недели.

## Этап 1. Каркас: значок в строке меню, ini, права (1 нед.)

Сложность: низкая. Цель — приложение запускается, живёт в строке меню, читает настройки.

- [ ] `NSStatusItem` + меню (пункты: Настройки, Открыть DKeys.ini, Автозапуск, О программе, Выход). Без значка в Dock (`LSUIElement = YES`).
- [ ] Читалка/писалка `DKeys.ini` (разбор секций, комментарии шаблона, значения по умолчанию, перечитка по изменению файла — `DispatchSource` на файл).
- [ ] Локализация: загрузка ru/en, `Tr("ID")`.
- [ ] Автозапуск через `SMAppService.mainApp` (пункт-галочка в меню).
- [ ] Единственный экземпляр (`NSRunningApplication` / lock-файл).
- [ ] **Мастер прав:** окно, которое проверяет и просит Accessibility (`AXIsProcessTrustedWithOptions`), Input Monitoring (`CGPreflightListenEventAccess`/`CGRequestListenEventAccess`) и Screen Recording (`CGPreflightScreenCaptureAccess`) и открывает нужный раздел Системных настроек. Пока право не выдано — функции его требующие отключены, а не падают.
- [ ] Логирование в `~/Library/Logs/DKeys.log` (аналог `build_dbg.cmd`).
- [ ] Скрипт сборки `build.sh`: сборка, подпись, копирование в `/Applications`, перезапуск (аналог `build.cmd`).

Готово, когда: значок в строке меню, `Выход` работает, настройки читаются, мастер прав показывает статус.

## Этап 2. Глобальные хоткеи и запуск (1 нед.)

Сложность: низкая. Хоткеи нужны всем следующим этапам.

- [ ] Менеджер хоткеев на `CGEventTap` (active tap, нужен Input Monitoring + Accessibility) — позволяет перехватывать комбинации и блокировать их. Для простых сочетаний — запасной вариант `RegisterEventHotKey` (Carbon, без прав).
- [ ] Разбор строк `Win+W` → `Cmd+W`/`Ctrl+Opt+W`, словарь клавиш и модификаторов, поддержка NumPad (`kVK_ANSI_Keypad*`), где он есть.
- [ ] Реестр действий: `ACTION_LIST` → enum/словарь Swift (`id`, имя в ini, аргумент) + `exec(action)`.
- [ ] Действия `run` (`NSWorkspace.open` / `Process`), `admin` (через `osascript ... with administrator privileges` — по запросу, редко), `py`, `script N`, `topmost` (окно поверх — через Accessibility `AXRaise`, ограниченно), `traymenu` (открыть меню значка).
- [ ] **Меню быстрого запуска** (`[Launcher]`, `[QuickRun]`, `runs/`): всплывающее окно-список у курсора (`NSPanel` без кражи фокуса), навигация стрелками/цифрами, `Enter`, `Shift+Enter` = показать в Finder.
- [ ] **Быстрый запуск** (`[QuickRun]`, v1.7): подменю в меню значка (`NSMenu`, пункты строятся из ini при каждом открытии); в окнах «Запуск», «Скрипты», «Записи» клавиша-переключатель (на Mac вместо `Num+` — например `Cmd+D` или `+`) добавляет/убирает пункт, пункты в списках помечены ★. В строке хранится **ссылка**, а не копия команды: `launcher:Название`, `scripts:Название`, `hotkey:<хоткей>`, `script:файл`, `record:файл`, `run:файл`; правка исходной команды действует и в быстром запуске; справа в подменю — хоткей пункта (`keyEquivalent`-подпись текстом, не настоящий shortcut). Имя строки уникально (`item (2)`…), ручные строки с обычной командой тоже работают. Сообщения «Добавлено/Убрано/Пункт не найден» — всплывающей подсказкой.
- [ ] Пункт меню значка «Запуск…» (бывший «Быстрый запуск…») и `traymenu` (`Win+Q` → хоткей на Mac): открыть меню значка у курсора (`NSStatusItem.menu.popUp(positioning:at:in:)`).
- [ ] Команда управления извне: `DKeys do "действие"` — через `NSDistributedNotificationCenter` или Unix-сокет в `Application Support`; выключено по умолчанию (`[Remote] Enabled`), коды возврата 0/2/3 сохранить. Маленький CLI-хелпер внутри бандла (`DKeys.app/Contents/MacOS/dkeys-do`) + симлинк `/usr/local/bin/dkeys`.
- [ ] Защита от повторного срабатывания и от «залипших» модификаторов (аналог «ждать отпускания модификаторов»).

Готово, когда: хоткей запускает программу, меню быстрого запуска открывается, `dkeys do "run Safari"` работает.

## Этап 3. Мультибуфер обмена, только текст (1–1,5 нед.)

Сложность: низкая–средняя. Ядро ценности программы.

- [ ] Опрос `NSPasteboard.general.changeCount` (таймер 0,2–0,5 с; событий у macOS нет) для истории буфера.
- [ ] Хранилище `memory/` — по файлу на буфер (формат совместим с Windows-версией: перенос между системами копированием папки).
- [ ] 9 буферов × 10 записей: «скопировать выделенное в буфер N» — отправить Cmd+C (`CGEvent`), дождаться смены `changeCount`, забрать, **вернуть прежний буфер** (основной не затрагивается).
- [ ] Вставка записи: положить в `NSPasteboard`, отправить Cmd+V, восстановить прежнее. Тут Windows-грабли («отложенный рендер», ожидание `GetOpenClipboardWindow`) заменяются своими: пауза/проверка `changeCount`, ожидание отпускания модификаторов хоткея до отправки клавиш (иначе Cmd+V превратится в Cmd+Opt+V).
- [ ] Окно меню буфера (`NSPanel`, не берёт фокус): цифры вставляют, `Del` удалить, `F2` править, `Ins` новая, `Ctrl+↑/↓` переставить, `←/→` другой буфер, `Tab` — история / запуск / скрипты. Политика заполнения: первая свободная ячейка, при полном буфере спрашивать номер.
- [ ] Пропуск секретов: игнорировать записи с типами `org.nspasteboard.ConcealedType` / `TransientType` (менеджеры паролей).
- [ ] Своя история буфера (вкладка «История»): ограничение длины, поиск.

Готово, когда: копирование в буфер N и вставка из меню работают в Safari, Terminal, VS Code, Notes.

## Этап 6. Расписание, автокопирование, секундомер и таймер (1,5 нед.)

Сложность: средняя.

- [ ] **Расписание** `[Schedule]`: разбор читаемых условий (`every 2d at 03:00`, `mon,wed,fri at …`, `monthly on 1,last`, `once …`, `on start/unlock/wake/idle/ac`). События: `NSWorkspace.didWakeNotification`, `DistributedNotificationCenter` (`com.apple.screenIsUnlocked`), `IOKit`/`NSProcessInfo` для сети питания, простой по `CGEventSourceSecondsSinceLastEventType`. Таймеры — внутри приложения (не `launchd`: приложение и так живёт). Выполнение пропущенного (`catchup`), `delay`.
- [ ] **Автокопирование выделенного мышью:** `CGEventTap` по `leftMouseUp` с двойным/тройным кликом или протяжкой → Cmd+C → без ответа. Исключения `Ignore=` по bundle id/имени приложения (`NSWorkspace.frontmostApplication`).
- [ ] **Секундомер/таймер:** до 5 окон-цифр (`NSPanel`, плавающие, прозрачный фон), двойной клик — старт/пауза, контекстное меню, избранное шаблонов; сигнал — `NSSound`/`AVAudioPlayer`, мигание фона; хранение сроков в ini, восстановление после перезапуска.
- [ ] Звук/уведомления: `UserNotifications` для напоминаний (нужно разрешение).

## Этап 7. Экранные утилиты: пипетка, рисовалка, лупа (2–3 нед.)

Сложность: средняя–высокая. Требуется право Screen Recording.

- [ ] **Пипетка:** `NSColorSampler` (готово в системе) или своя на `CGWindowListCreateImage`/`SCScreenshotManager`; цвет `#RRGGBB` в буфер; лупа 4× — своё окно с увеличением (`NSImage` + `NSCursor` трекинг).
- [ ] **Рисовалка на экране:** прозрачный окно-оверлей на каждом экране (`NSWindow`, `level = .screenSaver`, `ignoresMouseEvents` по режиму); инструменты — перо, маркер, стрелки, текст, номера, размытие (`CIGaussianBlur`), затемнение, лупа, подсветка курсора; режим «поверх стоп-кадра» (снимок `SCScreenshotManager`) и «поверх живого экрана»; объекты-фигуры с перемещением/поворотом/масштабом (Ctrl+мышь); результат — в буфер/PNG. Это самая большая UI-часть: Core Graphics + модель объектов сцены.
- [ ] Скриншоты/«shots»: папка `shots/`, области, мониторы (Retina-масштаб, несколько экранов с разным scale).
- [ ] Оверлеи ввода (клавиши/мышь на экране) — только после записи экрана (этап 9).

## Этап 9. Запись экрана и запись/воспроизведение действий (2–3 нед.)

Сложность: высокая.

- [ ] **Запись экрана:** `ScreenCaptureKit` (`SCStream`) + `AVAssetWriter` → H.264 mp4 в `~/Movies`; звук с микрофона (и опционально системный звук — с macOS 13 доступен в SCK); выбор монитора/области/окна, пауза, кнопка-кружок скрыта из кадра (`SCContentFilter(exceptingWindows:)`), курсор и клики подсвечиваются.
- [ ] **Оверлей ввода:** `CGEventTap` (клавиши/мышь) → рисование на видео и/или отдельный файл на зелёном фоне; пресеты формата input-overlay; **не показывать клавиши в полях пароля** (`IsSecureEventInputEnabled`).
- [ ] **Запись действий:** клавиши и мышь с паузами → скрипт (Python + `pyobjc`/`pynput`, либо собственный формат `.dkrec`), параметры скорости/повторов; «клик по кнопке» — через Accessibility API (`AXUIElement`, поиск по роли и названию) вместо `uiautomation`.
- [ ] **Подсветка курсора и кликов при записи** (v1.7+): кружок вокруг курсора (радиус 8–80 px, яркость 5–80 %, цвет) и расходящееся кольцо при клике (длительность 150–1500 мс, размер 12–120 px, отдельные цвета левого и правого клика, при отпускании кнопки — «последняя четверть» кольца, при зажатой кнопке подсветка ярче). Рисуется и **в видео** (при кодировании кадра, `CGContext` поверх `CVPixelBuffer`), и **на экране** во время записи: прозрачное окно, пропускающее мышь (`ignoresMouseEvents`, `level = .screenSaver`), исключённое из захвата (`SCContentFilter(exceptingWindows:)` — аналог `WDA_EXCLUDEFROMCAPTURE`), существует только пока видна кнопка записи. Положение клика — из `CGEventTap` (`leftMouseDown/Up`, `rightMouseDown/Up`, `mouseMoved`).
- [ ] **Окно «Курсор мыши в записи»:** предпросмотр, галочки «Подсвечивать курсор» и «Кольцо при клике», размеры кнопками −/+, выбор цветов (`NSColorPanel`); каждое изменение сразу пишется в `[Record]` ini (`Highlight`, `HighlightRadius`, `HighlightOpacity`, `HighlightColor`, `ClickRing`, `ClickMs`, `ClickSize`, `ClickColorLeft`, `ClickColorRight`) и подхватывается экранной подсветкой без перезапуска записи. Открывается пунктом «Настройки курсора и кликов…» и **средним кликом** по кнопке записи.
- [ ] **Оверлеи ввода по мониторам:** положение и масштаб оверлея хранятся отдельно для каждого монитора (`[OverlayPos]`, ключ `имя|монитор=x,y,масштаб`; на Mac идентификатор монитора — `CGDisplayCreateUUIDFromDisplayID`, а не номер, он меняется при переподключении); при переносе кнопки записи на другой монитор оверлей «прыгает» за ней и берёт сохранённое для этого монитора положение; настройка оверлеев — уровнем выше в меню записи (окно настройки не закрывает меню). Учесть Retina-масштаб и разные `backingScaleFactor` у мониторов.
- [ ] Меню «Записи», запуск из «Запуск»/расписания.

## Этап 11. Календарь (3–4 нед.)

Сложность: высокая. Больше всего нового UI.

## Этап 12. Громкость и дублирование звука (2–3 нед.) — самое тяжёлое

Сложность: самая высокая. На Windows это WASAPI loopback; на macOS аналога нет.

- [ ] **Стабильная громкость:** мониторинг пика системного звука на macOS невозможен без перехвата аудио: нужен **виртуальный аудиодрайвер** (BlackHole/Loopback) либо `ScreenCaptureKit` (захват системного звука, macOS 13+) только для измерения уровня; регулировка — `AudioObjectSetPropertyData` (`kAudioHardwareServiceDeviceProperty_VirtualMainVolume`) устройства по умолчанию. Учесть, что многие устройства (HDMI, USB) не поддерживают программную громкость.
- [ ] **Дублирование звука на второе устройство:** варианты: (1) Aggregate/Multi-Output Device через `AudioHardwareCreateAggregateDevice` (API есть, но дрейф часов и пропажа громкости), (2) захват системного звука `ScreenCaptureKit` + воспроизведение на втором устройстве через `AVAudioEngine` (задержка 100–300 мс), (3) требование BlackHole. Выбрать после прототипа; зафиксировать ограничения в README.
- [ ] Меню значка: выбор источника и приёмника, горячие клавиши вкл/выкл.
- [ ] Прототип сначала в отдельном проекте — риск «не получится так, как на Windows» самый большой именно здесь.

## Риски

- TCC: права Accessibility/Input Monitoring/Screen Recording сбрасываются при смене подписи; на Sequoia+ Screen Recording спрашивается периодически — продумать понятные подсказки.
- Secure Input (поля пароля, некоторые терминалы) блокирует `CGEventTap` — раскладка и оверлей ввода там не работают; не пытаться обходить.
- Нет NumPad на ноутбуках — схема хоткеев буферов нуждается в альтернативе.
- Этап 12 может быть урезан до «стабильная громкость без дублирования» или вовсе исключён, если ограничения аудио окажутся неприемлемыми.
- Python 3 не входит в macOS: все скриптовые функции должны проверять наличие и подсказывать установку.
