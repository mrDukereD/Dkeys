# DKeys

Крошечная portable-замена WireKeys (мультибуфер обмена + хоткеи + исправление раскладки RU↔EN), живёт в трее. Пользователь говорит по-русски, отвечать по-русски и коротко.

## Где что

- `src/dkeys.cpp` — вся программа (чистый WinAPI, один файл).
- `build.cmd` — сборка через MSVC в `obj\`, затем **убивает работающий DKeys** и кладёт exe в `D:\Progs\DKeys` (переменная `DEST`, аргумент `run` — запустить после сборки). Пользовательский DKeys работает от админа, а оболочка Claude — нет: `taskkill` получит Access denied и копирование не удастся. Тогда попросить пользователя закрыть DKeys (или запустить сборку от админа); чужой DKeys по имени не убивать вслепую.
- `src/dkeys.rc` + `src/dkeys.ico` — иконка exe и трея (оранжевая D с жёлтой K, картинка пользователя: мастер `src/icon.png` 512 px с прозрачным фоном), ресурс №1; `build.cmd` собирает `.rc` через `rc`. `python src/mkicon.py` (Pillow) пересобирает `dkeys.ico` из `icon.png`; большой кадр с палитрой, чтобы exe не распухал.
- `build_dbg.cmd` — `obj\DKeysDbg.exe` с `/DDKDEBUG`, лог в `%TEMP%\dkeys.log`.
- `D:\Progs\DKeys` — рабочая копия пользователя: `DKeys.exe`, `DKeys.ini`, `memory\` (его личные буферы, по файлу на буфер), `scripts\` (скрипты, раньше `py\`). **Не в git, не удалять и не править `memory\`.**
- Вне git (`.gitignore`): `obj/`, `dist/` (устарело, не используется), `WireKeys/` (старая чужая программа), `wkbackup.wkb3` (старые настройки).

## Ограничения (зачем)

- Без CRT (`/Zl`, вход `start`, свои memset/memcpy/memmove), `/GS- /Gs1048576`, кадры стека < 4 КБ (иначе `__chkstk`) — exe ~60 КБ и минимум памяти.
- В папке программы только exe и ini (+ `memory`, `scripts`) — portable, ничего лишнего.
- Только текст, буферы только на NumPad. Win+V по умолчанию не перехватывается.

## Грабли (почему сделано так)

- Владелец буфера обмена — окно на потоке хука (`DKClip`); вставка через отложенный рендер; перед Ctrl+V ждём `GetOpenClipboardWindow()==NULL` (слушатели вроде Viber открывают буфер сразу после изменения); перед отправкой клавиш ждём отпускания модификаторов хоткея; раскладку переключаем через ~250 мс после вставки.
- Редакторы без выделения копируют всю строку (Notepad++: `MSDEVLineSelect`; VS Code: `isFromEmptySelection` внутри `Chromium Web Custom MIME Data Format`) — `FixLayout` это распознаёт и заменяет строку. Повторное нажатие возвращает исходный текст.
- UIPI: хуки не видят окна, запущенные от админа (Total Commander у пользователя) — DKeys надо запускать от админа (пункт в меню трея). Всплывающее меню закрывается по таймеру-сторожу (смена активного окна / клик вне).

## Скрипты

Четвёртая вкладка всплывающего окна (после «Запуск», режим `PM_SCRIPTS`; действие `scripts`, Win+P в ini пользователя, пункт меню значка). Список — `*.py`, `*.bat`, `*.ps1` из папки `scripts` (без подпапок, по алфавиту): `tmp.py` (скрипт `pyrun`) всегда первый с меткой `T` и запускается клавишей T, остальные помечены цифрами 1-9,0 и запускаются цифрой (клавиши работают при пустом поиске); имя в списке — первая строка-комментарий `# Имя` (в bat `REM Имя` или `:: Имя`; shebang, `coding:` и `@echo` пропускаются), иначе имя файла; внизу — начало файла. Enter запускает через `RunPy` (как действие `py`, выделенный текст — в `DKEYS_SEL`; по расширению: `.py` — `Python=`, `.bat`/`.cmd` — `cmd /c`, `.ps1` — `powershell.exe -NoProfile -ExecutionPolicy Bypass -File`; проверено с аргументами через хоткей `py`); при `PyRunPause=1` (по умолчанию) скрипт идёт через `cmd /c "python скрипт & pause"` — окно не закрывается, виден вывод (действие `py` из хоткея окно не держит). Папка раньше называлась `py`: при старте, если `scripts` нет, а `py` есть, она переименовывается (`MoveFileW`). Имя действия `py` в хоткеях осталось. Поиск по имени и тексту, F2/Del не работают.

## Веб-камера

Окно предпросмотра на DirectShow (пункт «Вебкамеры…» в меню значка, действие `webcam`): меню окна «Камера» / «Разрешение» / «Полный экран» (F11, Esc — выйти). Граф строится при открытии и целиком уничтожается при смене камеры/разрешения и закрытии. Размер окна ≤ 3/4 монитора, пропорции держит `WM_SIZING`; для каждого разрешения берётся режим с максимальным fps, список по убыванию пикселей, по умолчанию самое большое. При закрытии окна в ini (`[Camera]`: `Device`, `Resolution`, `Window=x,y,w,h`) запоминаются камера, разрешение, положение и размер; читаются при старте/перечитывании. В списке камер есть виртуальные (DroidCam, OBS, Meta).

## Секундомер и таймер

Окно без рамки с одними цифрами (слой с попиксельной прозрачностью: фон — цвет с заданной непрозрачностью, цифры непрозрачны; alpha фона не ниже 1, иначе клики проходят сквозь). Перетаскивание за любое место, двойной клик — старт/пауза, правый клик и пункт «Секундомер и таймер» в меню значка — меню (время таймера: ввод «мин» / «м:с» / «ч:м:с» через `:` или пробел через `EditDialog` в однострочном режиме `g_edLine`, избранное `Favorites=секунды,…` до 10 штук; действие по окончании, цвета через ChooseColor, непрозрачность, размер). Действия `stopwatch`/`timer` для хоткеев. Настройки в `[Timer]`: `FontColor`, `BgColor` (RRGGBB), `BgAlpha`, `Size`, `EndAction` (0 сигнал, 1 выключить, 2 перезагрузить), `Pos`. Выключение/перезагрузка идёт через `shutdown /s|/r /t 30`, отмена — пункт меню (`shutdown /a`). Не тестировать выключение по-настоящему.

## Локализация

Все тексты интерфейса (меню, подсказки, тосты, заголовки) — только через `Tr(L_ID)`. Список `LANG_LIST` (id, ключ, русский текст по умолчанию) в начале `dkeys.cpp` — единственный источник; файл `langs\<Language>.ini` секция `[Text]` (`Language=ru` в `[General]`) создаётся при старте, недостающие ключи дописываются, значения из файла перекрывают встроенные. Формат — тот же ini (свой парсер, без CRT), не JSON. Новый текст: добавить строку в `LANG_LIST`, использовать `Tr(...)`; пробелы по краям значения парсер срезает (форматы вида `%s` вместо хвостовых пробелов). Не локализованы: комментарии `kIni`, имена хоткеев/клавиш, служебные строки. Подписи хоткеев в меню трея — `AddHk(...)` (хоткей берётся из текущих назначений).

## Пипетка

Действие `colorpicker`/`picker` (Win+Shift+C в ini пользователя, пункт меню трея). Namespace `PickNs`: снимок виртуального экрана (DIB) показывается во весь экран (замороженный), у курсора GDI-лупа 4x: круг 44 px = 11x11 пикселей источника, центральная клетка обведена, под лупой плашка с `#RRGGBB`. Цвет берётся из снимка (не с живого экрана: наложение слоя alpha=1 искажало бы значения). Клик/Enter — `#RRGGBB` в буфер (CF_UNICODETEXT), стрелки — сдвиг курсора на 1 px, Esc/правый клик — отмена.

## Рисовалка на экране

Действие `draw` (Win+S в ini пользователя; пункт «Рисовалка на экране…» в меню значка; повторное нажатие закрывает). Пространство `DrawNs` в `dkeys.cpp`, **GDI+ flat API** (`gdiplus.lib`, без C++-классов GDI+ — они тянут `new`; sqrt через SSE, `_fltused`). Один слоистый оверлей на монитор под курсором (`UpdateLayeredWindow`): статика — фон = снимок экрана; живой режим (Tab / кнопка) — фон прозрачный с alpha=1 (иначе клики проходят насквозь). Три поверхности (`bg` снимок, `base` фон+готовые фигуры, `back` + текущая фигура + панель); фигуры списком, undo/redo — счётчик `shN`, стирание — фигура `S_DEL` со ссылкой. Размытие — пикселизация из `bg` (в живом режиме по снимку на момент входа). Панель рисуется в том же слое (перетаскивается за фон), в результат не попадает. Копирование/сохранение в живом режиме прячет оверлей и снимает экран заново.
Этап 2: S — затемнить всё кроме прямоугольника (`Dim`), C — область сохранения (`CropRect`: снаружи затемнено только на экране, в буфер/PNG уходит вырезка; сразу после отпускания мыши область копируется в буфер и окно закрывается — `OnUp`), Z — линза-лупа 2/3/4x по толщине (`Lens`, круг: центр = точка нажатия, радиус = до курсора), H или кнопка — подсветка курсора (только на экране). Shift при рисовании: прямоугольник/овал — квадрат/круг, линия/стрелка — углы кратны 45°, перо — прямая. Индексы кнопок панели — enum `B_*` (инструменты 0..NTOOL-1).
Этап 3: зажатый Ctrl — выделение фигуры под курсором (рамка, 8 маркеров размера, маркер поворота над верхней гранью): тянуть внутри рамки — перенос, за маркер — размер (противоположный маркер неподвижен), за верхний кружок — поворот (угол как (cos,sin), без тригонометрии CRT; поворот у пера/линии/стрелки — точки, у прямоугольника/овала — поля `rc,rs` + матрица мира GDI+; размытие/затемнение/область — только перенос и размер, номер/текст/линза — только перенос). Правка идёт на месте от исходной копии `xo`; запись `S_XF` хранит копию «до» (`alt`), undo/redo меняют её местами с фигурой в слоте (`XSwap`). Пауза ~0,5 с на конце штриха пера — `Recognize` (линия / прямоугольник / овал по отклонению точек), D / Shift+D или кнопка (Shift+клик) — следующий / предыдущий монитор (`NextMonitor`, рисунки очищаются).
Клавиши: P перо, M маркер, A стрелка, L линия, R прямоугольник, O овал, T текст (Enter — готово, Shift+Enter — новая строка), N номер, B размытие, E ластик, 1–3 толщина, Tab живой/статика, Ctrl+Z/Ctrl+Y, Enter или Ctrl+C — в буфер (CF_DIB) и закрыть, Ctrl+S — PNG `Screen_ГГГГ-ММ-ДД_чч-мм-сс.png` в `shots\` рядом с exe (создаётся при первом сохранении; `[Draw] SaveDir=` — другая папка), Esc — закрыть. `[Draw]`: `Mode=live|static`, `Color=0-7`, `Width=0-2`, `SaveDir`.

## Запись экрана

Действие `record` (пункт «Запись экрана…» в меню значка, хоткей по желанию). Пространство `RecNs`: на экране только круглая кнопка 48 px (перетаскивается, позиция в `[Record] Pos`; правый клик — закрыть): красный кружок = начать, красный квадрат = остановить. Окно кнопки с `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` — в видео не попадает. Повторное действие `record`: идёт запись — стоп, кнопка открыта — старт, иначе показать кнопку. Запись идёт в потоке `Worker`: GDI `BitBlt` (+ курсор через `DrawIconEx`) монитора с кнопкой → Media Foundation `IMFSinkWriter` (H.264 mp4, вход RGB32 снизу вверх, метки времени по QPC, битрейт ~ пиксели×fps/10) → `Rec_ГГГГ-ММ-ДД_чч-мм-сс.mp4` в стандартную папку «Видео» пользователя (`SHGetFolderPathW(CSIDL_MYVIDEO)`; `[Record] Dir=` — другая папка). Звук: микрофон через WASAPI (16 бит 48 кГц стерео) -> вторая дорожка AAC; `Mic=` пусто - по умолчанию, `-` - без звука, иначе имя устройства (выбор в меню); потоки видео и звука пишут в один `IMFSinkWriter` под `CRITICAL_SECTION`. Ctrl+клик по кнопке во время записи - пауза; на паузе клик - продолжить, Ctrl+клик - стоп (время паузы вычитается из меток обоих потоков, кнопка показывает две полоски). `Screen=` 0 - монитор с кнопкой, 1-8 - монитор по номеру (порядок `EnumDisplayMonitors`), `all` - весь рабочий стол (меню: список мониторов с разрешениями); старый `AllScreens=1` читается как `all`. Область: Shift+клик по кнопке — затемнение монитора (окно с цветовым ключом, «дырка» = выбранная рамка), тянуть мышью, Shift — пропорции монитора, клик без рамки — сбросить; область (`areaOn`/`area`, только на время работы) важнее остальных настроек, на кнопке рамочка-индикатор. Win+Shift+R в ini пользователя. `NoTaskbar=1` (по умолчанию) снимает только рабочую область монитора (`rcWork`) — панель задач в кадр не попадает, ничего не скрывается. Настройки — подменю «Настройки записи» в меню значка; `[Record]`: `NoTaskbar`, `Cursor`, `Fps` (15/30/60), `Screen`, `Mic`, `Pos`. При выходе из DKeys запись дописывается.

Оверлей ввода (клавиши и мышь поверх записи): формат пресетов `input-overlay` (univrsal), папка `overlays\` рядом с exe (подпапки до 2 уровней; пресет = `имя.json` + `имя*.png` в той же папке, берётся самый длинный совпадающий png). Парсер JSON свой (типы элементов 0 текстура, 1 клавиша, 3 кнопка мыши, 4 колесо; остальные пропускаются), нажатый спрайт в атласе на `h+2` ниже обычного (колесо: варианты справа через `w+2`). Коды клавиш старого формата: скан-код, стрелки `0xE000|скан`, прочие E0-клавиши `0x0E00|скан`; состояние (`g_ioKey`, `g_ioMouse`, колесо) пишут хуки `LLKbd`/`LLMouse`. Режимы по пресету `[Overlay] имя=режим,x,y,масштаб` (0 выкл, 1 на видео, 2 отдельный mp4 на чистом зелёном `0xFF00FF00` — хромакей; «оба» нет, старое значение 3 читается как 1; x,y в ‰ кадра записи, масштаб %). Отдельный файл: `Rec_..._имя.mp4` рядом с основным, размер = размер пресета × масштаб. «Настроить положение и размер всех» (общий пункт рядом с «Папка overlays»): по окну-оверлею на каждый включённый пресет сразу (`OvProc`, до `NOVL`=6), подпись с именем, перенос мышью (выбранный поднимается наверх), углы/колесо (под курсором) — масштаб, Enter/правый клик — сохранить всё, Esc — отмена; показывает все клавиши нажатыми. «Показывать на экране» (`[Overlay] Show`, `ShowSync`): пока на экране кнопка записи, пресеты в режиме 1 видны на экране (прозрачные для кликов окна `DKRecShow`, `WDA_EXCLUDEFROMCAPTURE` — в запись не попадают, таймер 33 мс), чтобы видеть, что они перекрывают. Производительность: атлас клонируется в PARGB, при масштабе 100% интерполяция NearestNeighbor (с bicubic на PNG кадр занимал ~0,5 с); короткие нажатия держатся на видео минимум 70 мс (`g_ioHit`). Меню пресетов группируется по подпапкам `overlays\`. Приватность: `HidePasswords=1` (по умолчанию) — поток `PwdWorker` (UI Automation, `IsPassword` у элемента в фокусе) гасит показ клавиш в поле пароля; при включении режима тост-предупреждение, что клавиши видны в видео.

## Стабильная громкость

Действия `volume` (вкл/выкл, Win+A в ini пользователя) и `volumeset` (окно, Win+Shift+A), подменю «Стабильная громкость» в меню значка (только включить и открыть окно); все настройки — в окне. Пространство `VolNs`, поток `Worker` (опрос раз в 15 мс, живёт пока режим включён или открыто окно): `IAudioMeterInformation::GetPeakValue` устройства вывода (по умолчанию или `Device=` по имени; смена устройства по умолчанию ловится раз в секунду) и `IAudioEndpointVolume`. Счётчик меряет сигнал **до** мастер-громкости (проверено: пик 0,5 при 10 % и при 20 %), поэтому формула без деления на громкость: пик S выше порога T → громкость `C*T/S` (C = потолок `Ceiling`), атака сразу; возврат плавно (2 %/тик) по удержанному пику (спад ~2 с), чтобы не качало. Тихое не подтягивается; `Boost=N`: если удержанный пик×C < 25 % порога, громкость может быть до C×(1+N/100). Ползунком системной громкости режим управляет сам (ручные изменения не отличаются, перекрываются). Выключение или выход из DKeys возвращает громкость к C; при убийстве процесса громкость остаётся как была. `Ceiling` по умолчанию = громкость на момент первого включения. Окно (`DKVol`, GDI с двойной буферизацией, таймер 33 мс): полоса текущего пика с перетаскиваемой красной чертой порога, ползунок максимальной громкости, ползунок «Подтягивать тихое» (0-50 %, шаг 5), строка выбора устройства вывода (меню по клику), переключатель. Не проверялось на реальных играх; первые 15-50 мс резкого пика проходят до реакции.

## Дублирование звука

Подменю «Дублирование звука» в меню значка: «Включено», «Источник» (устройство по умолчанию или любое устройство вывода), «Приёмник» (список устройств вывода); ids 700-759 (DupNs::Menu/Cmd, меню остаётся открытым). `[Duplicate]`: `Enabled`, `Source` (пусто - по умолчанию, следует за ним при смене), `Sink` (имя устройства). Поток `DupNs::Worker`: WASAPI loopback источника (`AUDCLNT_STREAMFLAGS_LOOPBACK`, формат микса источника) -> `IAudioRenderClient` приёмника (`AUTOCONVERTPCM`); запас 50 мс тишины, если в буфере приёмника > 150 мс - кадры выбрасываются (дрейф часов); выбор перепроверяется каждые 100 мс, при ошибке или отсутствии приёмника - повтор раз в секунду. Источник = приёмник игнорируется (петля). Хоткея нет. Проверено: тон на устройстве по умолчанию -> тот же пик на виртуальном приёмнике (Steam Streaming Speakers); на реальных наушниках на слух и рассинхрон с видео не проверялись.

## Регистратор камеры

Меню окна камеры «Регистратор»: «Записывать кадры» (галка) и «Настройки регистратора…» (кадр раз в N с, папка, лимит МБ, качество JPEG). Настройки у каждой камеры свои — секция ini `[Cam:имя]` (`Enabled`, `Interval`, `Dir`, `LimitMB`, `Quality`); настраивается камера, выбранная в окне. Кадры: `Папка\Камера\ГГГГ\ММ\ДД\чч-мм-сс.jpg`, папка по умолчанию — «Изображения»\DKeys; при превышении лимита удаляются старые (до 95 %). Пока включена хоть одна камера, поток `CamRecNs::Worker` снимает кадры и после закрытия окна; на значке трея снизу справа красная точка. Если камеру держит окно превью, кадр берётся из его графа (SampleGrabber в превью, колбэк по запросу); иначе камера открывается отдельным графом (камера -> SampleGrabber RGB24 -> NullRenderer), при интервале < 10 с остаётся открытой, иначе закрывается после кадра. При открытии превью регистратор отпускает камеру. Дополнительно (`Shot`/`Grid`/`InHours`): `SkipDark` (по умолчанию 1) — кадр пропускается, если средняя яркость сетки 32x24 < 6; `Motion` 1-50 — писать, только если средняя разница яркости сетки с последним сохранённым кадром >= порога (0 выкл); `Stamp` — дата и время на кадре (GDI+ текст с тенью); `MinFreeMB` (500) — не писать при нехватке места на диске; `From`/`To` — часы работы (0-24, через полночь допустимо); кнопка «Открыть папку» в окне настроек. Проверено на USB-камере без окна превью (числами, кадры не открывались).

## Тесты и безопасность

- Автотестов нет; проверялось вручную и через SendInput-скрипты (Python ctypes) с тестовым окном `EDIT`.
- Никогда не слать тестовые клавиши в чужие окна: окно искать по PID запущенного тестом процесса и проверять фокус перед каждой клавишей. У пользователя открыты Notepad++ и VS Code с несохранённой работой.
- Не убивать `notepad`/`cmd`/прочее по имени; тесты не должны трогать настоящие `memory\*.txt` (работать на копии).
