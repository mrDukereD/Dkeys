# DKeys

Крошечная portable-замена WireKeys (мультибуфер обмена, хоткеи, исправление раскладки, экранные утилиты), живёт в трее. Пользователь говорит по-русски, отвечать по-русски и коротко. Что умеет программа — в `README.md`, как устроено — в коде.

## Где что

- `src/dkeys.cpp` — вся программа (чистый WinAPI, один файл). `src/dkeys.rc` + `src/dkeys.ico` — версия и иконка (ресурс №1; `python src/mkicon.py` пересобирает ico из `icon.png`).
- `build.cmd` — сборка MSVC в `obj\`, затем **убивает работающий DKeys** и копирует exe в `D:\Progs\DKeys` (`DEST`, аргумент `run` — запустить). Пользовательский DKeys работает от админа, а оболочка Claude — нет: `taskkill` и копирование не пройдут. Тогда попросить пользователя закрыть DKeys; чужой процесс по имени не убивать. `build_dbg.cmd` — отладочная сборка с логом `%TEMP%\dkeys.log`.
- `D:\Progs\DKeys` — рабочая копия пользователя (exe, `DKeys.ini`, `memory\`, `scripts\`, `records\`, …). **Не в git; `memory\` не трогать и не удалять.**
- Вне git (`.gitignore`): `obj/`, `dist/`, `WireKeys/`, `wkbackup.wkb3`.

## Ограничения

- Без CRT (`/Zl`, вход `start`, свои memset/memcpy/memmove, нет `wcschr`/`abs` и т.п.), `/GS- /Gs1048576`, кадры стека < 4 КБ (иначе `__chkstk`): маленький exe, минимум памяти. GDI+ — только flat API.
- Portable: рядом с exe только exe, `DKeys.ini` и служебные папки (`langs`, `memory`, `scripts`, `runs`, `records`, `overlays`, `shots`).
- Только текст в буферах (плюс картинки), буферы на NumPad. Win+V по умолчанию не перехватывается.
- Не плодить зависимости и размер: exe должен оставаться небольшим.

## Грабли

- Владелец буфера обмена — окно на потоке хука; вставка через отложенный рендер; перед Ctrl+V ждать `GetOpenClipboardWindow()==NULL`; перед отправкой клавиш ждать отпускания модификаторов хоткея.
- UIPI: хуки не видят окна, запущенные от админа; DKeys надо запускать от админа.
- Диалоги и `Toast` — только из главного потока.
- Окна кнопок записи исключены из захвата экрана (`WDA_EXCLUDEFROMCAPTURE`): скриншотом их не проверить.

## Локализация

Все тексты интерфейса — только через `Tr(L_ID)`; список `LANG_LIST` в начале `dkeys.cpp` — единственный источник, файл `langs\<Language>.ini` создаётся при старте. При изменении текста по умолчанию меняется и ключ (иначе у пользователя останется старый). В значениях нет переводов строк. Не локализуются комментарии шаблона ini, имена хоткеев и служебные строки.

## Тесты и безопасность

- Автотестов нет; проверка вручную и скриптами (Python ctypes, `SendInput`) **только на изолированной копии** exe (поменять имя мьютекса `DKeys_single_instance` в копии, свой ini) в scratchpad.
- Не слать тестовые клавиши в чужие окна (у пользователя открыты Notepad++ и VS Code с несохранённой работой): окно искать по PID запущенного процесса, проверять фокус. Не убивать процессы по имени. Не трогать настоящие `memory\`. Выключение/перезагрузку не тестировать по-настоящему.
- В скриптах Python для Windows не использовать heredoc с кириллицей и обратными слэшами в Bash — писать файл инструментом Write.

## Git

Коммитить, пушить и выкладывать релиз только по просьбе. Remote: github.com/mrDukereD/Dkeys, ветка `main`. «Версию не повышай» — заменить asset существующего релиза (`gh release upload --clobber`), без новой версии.

## README и релиз

- README: «Возможности» — по блоку на функцию, порядок: буферы, раскладка, запуск, скрипты `.dpy`, рисовалка, пипетка, запись экрана, диктофон, голосовой набор и команды, запись действий, расписание, автокопирование, секундомер и таймер, вебкамера и видеорегистратор, стабильная громкость, дублирование звука. Новую функцию ставить по смыслу рядом с родственной. Размер exe в текстах не указывать.
- Версия одна и та же в README («Скачать готовый exe»), «О программе» (`L"1.x"`) и `dkeys.rc` (4 места). При новой функции обновлять README, «О программе» и перечень в релизе.
- При каждой новой версии сразу обновлять exe в `D:\Progs\DKeys`. Если DKeys запущен и копирование не проходит — `D:\Progs\DKeys\DKeys.exe do exit` (нужен `[Remote] Enabled=1`), подождать и скопировать; запустить DKeys снова должен пользователь (он работает от админа).
- История версий — `CHANGELOG.md`: раздел `## vX.Y` на версию (дата, ссылка на релиз, что нового). Описание релиза: «Что нового» (то же, что в CHANGELOG), затем «Что умеет» — краткий перечень всего (~10 пунктов по тем же блокам, короче README), в конце ссылки на README и CHANGELOG.

## Планы

- MCP-сервер на python (отдельный файл в репозитории, не в exe): тонкая обёртка над `DKeys.exe do "действие"`, чтобы DKeys управлялся агентами без терминала (запись, таймер, скрипт N, запуск, вставка). Делать только по просьбе; учесть, что `[Remote]` даёт запуск чего угодно от админа.
