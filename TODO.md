### Текст: зачем приложению данные (justification, по-английски - так принимают)

**App description.** DKeys is a small portable Windows tray utility (clipboard history, hotkeys, screen tools). Its optional Calendar module shows the user's own Google Calendar events and Google Tasks in a desktop window, lets the user create, edit and delete them, and shows reminders. The app has no server: it runs entirely on the user's computer.

**Why `calendar` scope.** The app displays the signed-in user's calendar events in a desktop calendar window and writes back events the user creates, edits or deletes there, plus reminders. Read-only access would not allow editing or creating events, which is the core feature. We request the full `calendar` scope because the app creates, updates and deletes events and reads calendar settings (default reminders, time zone). We do not use any narrower scope because `calendar.events` alone does not cover reading the calendar list and defaults needed for the calendar picker.

**Why `tasks` scope.** The app shows Google Tasks that have a due date as all-day items in the same calendar view and lets the user mark a task completed or edit its title and due date, so tasks appear next to events as in Google Calendar. This requires read and write access to tasks.

**Data handling.** All data is fetched directly from Google to the user's own computer and stored only locally (events in a local file, tokens in a local folder). Nothing is sent to the developer or to any third party; there is no developer-operated server. Data is not used for advertising, profiling or training of AI/ML models, and is not sold or shared. Humans do not read the data. The app's use of Google user data complies with the Google API Services User Data Policy, including the Limited Use requirements. The user can revoke access at any time at https://myaccount.google.com/permissions or by deleting the `calendars\*.state` folders.

## Календарь (в обсуждении, ничего не сделано)

Цель: общий календарь DKeys с двусторонней синхронизацией через скрипты-провайдеры (Google, Apple/iCloud, любой CalDAV). DKeys хранит и показывает события, скрипты в `calendars\` общаются с внешними сервисами.

### Решения

- **Формат обмена и хранения — iCalendar (ICS).** `VEVENT` уже умеет `RRULE`, `EXDATE`, `TZID`, `VALARM`. Свой JSON-парсер в exe не нужен, а питоновские библиотеки (`caldav`, `icalendar`) говорят на ICS из коробки. Локальный календарь — обычный `memory\calendar\local.ics`, импорт и экспорт получаются сами.
- **Договор провайдера** (скрипт в `calendars\`, питон, как `.dpy`): `скрипт pull [--since ...]` печатает ICS в stdout, `скрипт push` читает со stdin изменения (создано / изменено / удалено, с `X-DKEYS-OP`) и печатает id и версию (etag) результата. Вход в аккаунт, токены, библиотеки — внутри скрипта и его папки.
- **Ключ события:** источник + id + etag; у каждого события признак «удалено» (надгробие), иначе удалённое вернётся при синхронизации.
- **Конфликты:** выигрывает последнее изменение, запись в лог.
- **Повторы:** хранить `RRULE` как есть, разворачивать только для показа (подмножество: `FREQ`, `INTERVAL`, `BYDAY`, `BYMONTHDAY`, `COUNT`, `UNTIL`, `EXDATE`). Правка одного вхождения (`RECURRENCE-ID`) — отдельным этапом.
- **Часовые пояса:** событие хранится с `TZID`, для показа переводится в локальный. Нужна таблица IANA → имена Windows (около 150 записей) для `SystemTimeToTzSpecificLocalTimeEx`.
- **Окно календаря** рисуется самим DKeys (GDI, как остальные окна), без зависимостей.

### Интерфейс

- Пункт меню значка «Календарь» под секундомером и таймером; клик сразу открывает окно на месяц или неделю (по настройке), действие хоткея `calendar`.
- Окно: сверху `‹ Сегодня ›`, заголовок («Ноябрь 2026»), переключатель `Месяц | Неделя | День | Список`, кнопка «+ Событие». Слева мини-месяц для перехода и список календарей-источников с цветом и галочкой «показывать».
- Месяц: сетка с плашками событий цвета источника, «+N ещё», номера недель по настройке. Клик по дню — строка быстрого ввода («завтра 15:00 встреча»), двойной клик по событию — редактор.
- Неделя и день: сетка по часам, события блоками, линия «сейчас», полоса «весь день» сверху; позже перетаскивание и растягивание мышью.
- Список (повестка): ближайшие события по дням, тот же вид пригодится для голоса и трея.
- Редактор события: название, «весь день», начало и конец (дата и время), часовой пояс, повтор (нет / каждый день / неделя / месяц / год / свой, конец), напоминания (несколько, «за N минут/часов/дней»), место, описание, **источник — переключатель радио** (Локально, Google, iCloud…).
- Перенос между источниками: при смене радио и сохранении событие создаётся в новом и удаляется в старом; галочка «оставить копию в прежнем».
- Удаление: «Удалить везде» (и в источнике) и «Убрать только из DKeys» (остаётся в источнике, скрыто локально и не возвращается при синхронизации). Формулировки уточнить.
- Настройки (в окне календаря): вид по умолчанию (месяц/неделя), первый день недели, 24 часа, номера недель, рабочие часы, напоминание по умолчанию, источник по умолчанию, интервал синхронизации, цвета календарей.

Неделя/день: сетка по часам с прокруткой колесом (при открытии - к `WorkStart`, вне рабочих часов - к текущему часу), полоса «весь день», перекрывающиеся блоки колонками, красная линия «сейчас», клик по пустой ячейке - новое событие на этот час, двойной клик - редактор, перетаскивание блока (шаг 15 мин; у повторяющихся только время) и растягивание нижнего края, `Esc` - отмена; правка сохраняется как в этапе 3. Список: 30 дней вперёд от выбранного дня, заголовки «Сегодня/Завтра», Up/Down/Tab, Enter/двойной клик. Проверено на изолированной копии (перенос и растягивание сохраняются в local.ics). Не проверено: светлая тема, DPI≠96; перетаскивание вхождения серии сдвигает всю серию.
8. **Голос и скрипты — сделано** (разбор подкоманд, формат ответов и посылка скрипта события — `src/calendar.h` (`CalCmdParse`, `AgendaFormat`, `NextOcc`, `HookPack`), проверки в `tests\caltest.cpp`; действия и хуки — `CalAct`/`CalHookRun` в `src/dkeys.cpp`). **Действие `calendar`:** `add|remind ФРАЗА` (быстрый ввод этапа 3 в `DefaultSource`, `remind` - напоминание в момент начала, тост «Добавлено: …»; окно открыто - в его хранилище, закрыто - файл источника), `today|tomorrow|week` (окно на дне/неделе), `agenda [today|tomorrow|week]` (тост до 6 строк), `next` (тост «через N»), `sync`. **Голос:** в `{TEXT}` (новая подстановка `commands.ini` — остаток фразы как есть) добавлены «добавь встречу|запиши в календарь|напомни …», «что у меня сегодня|завтра|на неделе», «следующее событие», «открой|синхронизируй календарь»; блок дописывается в `langsu.commands.ini`, если в нём нет команд `calendar`. **Скрипты по событию:** `[Calendar] OnReminder|OnCreate|OnChange` — действие DKeys, поля в `DKEYS_EVENT_TITLE/_START/_END/_PLACE/_SOURCE/_UID`, запуск через очередь `Defer`; OnCreate/OnChange — из окна (редактор, быстрый ввод, перетаскивание) и `calendar add`, не из синхронизации; зацикливание: `DKeys.exe do` из скрипта события помечается (`DKEYS_EVENT_UID` в окружении) и OnCreate не вызывает. Проверено на изолированной копии (`calendar add/remind/agenda/next`, хук с `do`, дописывание commands.ini); **не проверено живым голосом:** сопоставление `{TEXT}` по распознанной речи.
